# Product Requirements Document (PRD)

## Return & Rebuy Agent


## 1. Executive Summary

**Product Name:** Return & Rebuy Agent (working title)

**One-liner:** An AI agent that automatically detects post-purchase price drops, buys the item at the lower price, and orchestrates the return of the original purchase—capturing savings that consumers otherwise leave on the table.

**The Insight:** Amazon and most major US retailers do not offer post-purchase price adjustments or direct refunds for price drops. The official workaround is a cumbersome two-step process: **return the original item, then repurchase it at the lower price**. Most consumers never do this because of the effort involved. Return & Rebuy Agent automates this entire workflow end-to-end.

**Why People Pay:** Direct, measurable ROI. If the agent saves a user $30 on a price drop, taking a 15% cut ($4.50) is painless because the user would not have captured that savings otherwise.

**Hackathon Fit:** Prava powers the critical "buy the new one" transaction. OpenAI handles receipt parsing. Visa Intelligent Commerce enables secure, conditional spending controls.


## 2. Market Context & Opportunity

### 2.1 The Return Market Is Massive

- US retail returns reached **$849.9 billion** in 2025, representing 15.8% of all retail sales
- **19.3% of online sales** are expected to be returned in 2025—roughly 1 in 5 online purchases
- E-commerce accounted for 16.2% of total retail sales in Q1 2026, up from 15.3% in Q1 2025

### 2.2 The Price Drop Problem

- Amazon uses **dynamic pricing algorithms** that continuously adjust product costs based on market demand, competitor activity, and inventory levels
- **Amazon does not offer price matching or direct refunds** for post-purchase price reductions
- The only reliable workaround is the **"return and rebuy"** strategy
- For sellers moving 1,000+ units monthly, even a **1% price drop can trigger 15-25% spikes in returns**

### 2.3 The Consumer Behavior Gap

- Most consumers **never** claim price drops due to the hassle of:
  - Monitoring prices manually
  - Initiating a return
  - Repackaging and shipping the item
  - Waiting for the refund
  - Placing a new order
- This creates a **clear arbitrage opportunity** for an automated agent


## 3. Problem Definition

### 3.1 The Core Problem

Consumers overpay for items when prices drop after purchase. Retailers will not refund the difference directly. The only solution—returning and rebuying—requires too much effort for most people to bother.

### 3.2 User Pain Points

| Pain Point | Description |
|------------|-------------|
| **Missed savings** | Consumers lose money on price drops they never notice |
| **Return friction** | Repackaging, printing labels, driving to UPS is a hassle |
| **Upfront cash** | To rebuy at the lower price, you need to front the money before the refund hits |
| **Timing anxiety** | Price drops must be caught within the return window (typically 30 days) |
| **Forgetfulness** | Most people don't remember to check prices after purchase |

## 5. Solution Overview

### 5.1 High-Level Workflow

```
┌─────────────────────────────────────────────────────────────────┐
│                        USER FLOW                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. USER FORWARDS RECEIPT                                       │
│     └─> Email receipt → agent inbox                            │
│     └─> OR upload screenshot/PDF                               │
│                                                                 │
│  2. AGENT EXTRACTS DATA (OpenAI)                               │
│     └─> Order ID, SKU/ASIN, Purchase Price, Return Deadline   │
│     └─> User confirms/corrects in dashboard                   │
│                                                                 │
│  3. AGENT MONITORS PRICE (Cron Job)                            │
│     └─> Checks current price every 6 hours                    │
│     └─> Compares to purchase price                            │
│                                                                 │
│  4. PRICE DROP DETECTED                                        │
│     └─> IF Current_Price < Purchase_Price                     │
│     └─> AND Today < Return_Deadline - 5 days                  │
│                                                                 │
│  5. AGENT EXECUTES "RETURN & REBUY"                            │
│     ├─> a) Buys new item at lower price (PRAVA)              │
│     ├─> b) Initiates return on original order (API/Form)     │
│     └─> c) Notifies user with summary                         │
│                                                                 │
│  6. USER SHIPS OLD ITEM                                        │
│     └─> Prints label, drops off package                       │
│                                                                 │
│  7. REFUND PROCESSED                                          │
│     └─> Original payment refunded to user's card              │
│     └─> Agent takes % cut of savings via Prava split         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 7.4 Price Monitoring Implementation

**Option A: Apify API (Recommended)**
- Use Apify's Amazon Price Monitor API
- Pricing: ~$0.35 per 1,000 results
- Returns current price, availability, ratings
- Simple REST API with Python/JavaScript clients

**Option B: Direct Scraping**
- Use Playwright/Puppeteer for headless browser
- More fragile but no API cost
- Risk of being blocked

**Recommendation:** Start with Apify for reliability, fallback to scraping for non-Amazon retailers.

### 7.5 Return Initiation Implementation

**Option A: Retailer API (Where Available)**
- Amazon: Use Amazon's Return API (Seller Central or MWS)
- Best Buy, Target: Check for public return APIs

**Option B: Browser Automation**
- Use Playwright to simulate user login and return initiation
- More fragile but works across all retailers

**Option C: Email-Based Returns**
- Some retailers accept return requests via email
- Agent drafts and sends the email

**Recommendation for MVP:** Browser automation with Playwright for Amazon guest checkout returns (no login required for some return types).


## 8. Prava Integration Deep Dive

### 8.1 Why Prava Is Essential

Prava is not just a payment button—it is the **engine that enables the entire "rebuy" step**:

| Requirement | Prava Feature |
|-------------|---------------|
| Secure card storage | Tokenized card credentials, never touches raw card data |
| One-click checkout | Complete purchase without redirecting user |
| Spend controls | Tokens scoped to specific merchant, amount, and expiry |
| User approval | Biometric verification for every transaction |
| PCI compliance | PCI DSS Level 2 certified |
| Universal merchant coverage | Works with any merchant accepting Visa/Mastercard |

### 8.2 Prava Integration Flow

```python
# Pseudo-code for Prava rebuy flow

from prava import PravaClient

# 1. User connects card once (stored as token)
client = PravaClient(api_key=os.environ["PRAVA_API_KEY"])
card_token = client.create_card_token(
    user_id=user.id,
    card_number="4111...",
    expiry="12/26",
    cvc="***"
)

# 2. When price drop detected, create scoped payment token
payment_token = client.create_payment_token(
    card_token=card_token,
    merchant="amazon.com",
    amount=new_price,
    expiry=datetime.now() + timedelta(minutes=5),  # Single-use
    description=f"Rebuy {product_name} at lower price"
)

# 3. Execute checkout with Prava's browser automation
result = client.checkout(
    payment_token=payment_token,
    url=product_url,
    shipping_address=user.address,
    billing_address=user.billing_address
)

# 4. Webhook confirms completion
# POST /webhook/prava
# {
#   "transaction_id": "txn_123",
#   "status": "completed",
#   "amount": 79.99,
#   "merchant": "amazon.com"
# }
```

## 12. Constraints & Limitations

### 12.1 Technical Constraints

| Constraint | Mitigation |
|------------|------------|
| **Amazon no longer offers formal price matching** | We use return-and-rebuy workaround, not price matching |
| **Return window varies by category** (14–30 days) | Agent checks product-specific return policy |
| **Item must be in new, unused condition** | User must not open/use item if they want to return it |
| **Scraping can be blocked** | Use Apify API for reliability; fallback to browser automation |
| **Prava production access is temporary** | Hackathon production access valid Aug 1–8 only |

### 12.2 Product Constraints

| Constraint | Mitigation |
|------------|------------|
| **MVP: Amazon only** | Target the largest e-commerce platform first |
| **Guest checkout only** | Avoid 2FA/captcha issues with logged-in sessions |
| **User must ship return** | Physical return still requires user action (print label, drop off) |
| **Upfront cash required** | User must have available credit for rebuy before refund hits |

### 12.3 Risk Mitigation

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|------------|
| Price scraping fails | Medium | High | Use Apify API + multiple fallback sources |
| Return automation breaks | Medium | Medium | Alert user to complete return manually |
| User doesn't ship return | Medium | Low | User keeps both items; no refund; agent still earns on rebuy |
| Prava transaction fails | Low | High | Retry logic; alert user if persistent |
| Retailer changes return policy | Low | High | Monitor policy changes; update automation |
